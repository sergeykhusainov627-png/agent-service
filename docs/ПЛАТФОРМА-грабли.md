# Грабли платформы и проверенные приёмы

Рабочий справочник проекта: что уже ломало код на стенде и чем это лечится.
Ведём по мере нахождения — чтобы не повторять дважды.

## Грабли

### 1. `Mod` нельзя использовать как имя
**Симптом:** компилятор отказывается: «`Mod` не может быть именем переменной».
**Причина:** `Mod` — оператор (остаток от деления), а не идентификатор.
**Лечение:** параметр/переменную назвать `ModuleId`, `Rest`, `Remainder`.
**Ловушка:** так же нельзя `Div`, `Is`, `As`, `Not`, `And`, `Or`, `Xor`, `New`,
`Null`, `True`, `False`, `Begin`, `End`, `If`, `Then`, `Else`, `For`, `To`,
`Do`, `While`, `Repeat`, `Try`, `Except`, `Finally`, `Var`, `Const`, `Sub`,
`Function`, `Class`, `Property`, `Object`, `Array`, `Of`, `Public`, `Private`,
`Protected`, `Friend`, `Shared`, `Final`, `Raise`, `Return`, `Break`, `Continue`,
`On`, `Case`, `Select`, `With`, `Get`, `Set`, `Self`, `Dispose`.
**Где ловится:** `node tools/agent-cli.js lint <файл.fore>` — проверка идёт
автоматически (53 зарезервированных слова).

### 2. `Directory.CreateDirectory` падает на существующей папке
**Симптом:** окно «Форсайт. Аналитическая платформа — Ошибка»:
«Невозможно создать файл, так как он уже существует», класс ошибки `CPIOException`.
**Причина:** в этой платформе метод бросает исключение, если папка есть,
в отличие от .NET, где он просто ничего не делает.
**Лечение:** сначала проверка.
```
If Not Directory.Exists(Path) Then
	Directory.CreateDirectory(Path);
End If;
```

### 3. У `Form` нет свойства `Caption`
**Симптом:** ошибка компилятора «Неизвестный идентификатор 'Caption'» на строке
вида `Self.Caption := "..."` в модуле формы.
**Причина:** у формы в этой платформе нет `Caption`. Заголовок окна берётся из
**наименования объекта формы** в репозитории, а из кода настраиваются `Width`,
`Height` и свойства `IControl`.
**Лечение:** строку `Self.Caption := ...` удалить, заголовок задать в свойствах
объекта формы в навигаторе.
**Осторожно:** привычка с других платформ (Caption у окна/формы) здесь не
работает, и подсказку даёт только компилятор.

### 4. Незакрытый читатель/писатель держит файл
**Симптом:** `File.Delete` (или повторное открытие) падает с `CPIOException`
«Процесс не может получить доступ к файлу, так как этот файл занят другим
процессом», хотя файл никто не держит. Платформа при этом показывает модальное
окно ошибки — и если это обработчик таймера, таймер встаёт до нажатия «ОК».
**Причина:** `File.OpenTextReader` / `OpenTextWriter` открывают поток, а
`Flush` его не закрывает. В `DEPLOYTOOL.fore:709` есть комментарий «`Close`
в справке не вызывается — не вызываем и мы»: для чтения это работает, но если
после чтения файл нужно **удалить или перезаписать** — поток обязан быть закрыт.
**Лечение:** явно освобождать ресурс и обнулять ссылку.
```
Reader := File.OpenTextReader(Path);
// ... чтение ...
Dispose Reader;
Reader := Null;
```
и так же для писателя после `Flush`:
```
TxtWriter.WriteString(Text);
TxtWriter.Flush;
Dispose TxtWriter;
TxtWriter := Null;
```
**Вывод по стилю работы с файлами в этой платформе:** «открыл → прочитал →
освободил»; операции с файлами, которые могут бросить исключение, лучше
выполнять идемпотентно и защищать `Try`, потому что ошибка файловой операции
показывается модальным окном и может заблокировать обработчик события.

### 5. `ReadToEnd` на пустом файле бросает исключение
**Симптом:** «Достигнут конец потока».
**Лечение:** сначала проверять `Reader.Eof`.
Источник: `DEPLOYTOOL.fore:717`.

### 6. Кодировку задавать ДО первой записи
**Симптом:** кириллица уходит в системную ANSI и портится.
**Лечение:** `Writer.Encoding := CodePage.UTF8;` сразу после `OpenTextWriter`.
Источник: `EditorSpike.fore:453`.

### 7. `Bin.Version` — не строка
**Симптом:** `.ToString` на `IForeAssemblyBinary.Version` даёт ошибку.
**Лечение:** склеивать значение напрямую: `"Version = " + Bin.Version`.
Источник: `EditorSpike.fore:252`.

### 8. `GetMetadata` на стенде не работает
**Симптом:** документ метаданных не разбирается (`parsed = FALSE`), падение
в `XMLLib2.dll`.
**Лечение:** не использовать; словарь API брать из `docs/forsite/api-index.txt`.
Источник: `EDITOR-TZ.md:43`.

### 9. `IForm.Content` (XML формы) править нельзя
**Симптом:** после правки форма теряет работоспособность.
**Лечение:** текст формы править через её модуль (`IModule.Text`).
Источник: справка `IForm.Content` — прямое предупреждение.

### 10. Исключение в обработчике события модальной формы закрывает окно
**Симптом:** «кликнул — форма исчезла».
**Лечение:** каждый обработчик события — в `Try…Except`, ошибку в журнал.

### 11. `IAssembly` не имеет свойства `Id`
**Симптом:** компилятор: «Неизвестный идентификатор 'Id'».
**Причина:** у `IAssembly` только `Modified`, `Permanent`, `References`
(справка, `api-index.txt`). Свойства `Id` у него нет.
**Лечение:** идентификатор брать через описание объекта:
```
ADesc := A As IMetabaseObjectDescriptor;
Return ADesc.Id;
```
**Проверка:** `node tools/check-members.js --list IAssembly` покажет состав типа.

### 12. `IAssembly.References` — строка, а не коллекция
**Симптом:** «ссылок 0» там, где они есть; или ошибка при `.Count`/`.Item`.
**Причина:** справка: `References: String` — список имён сборок через `;`.
**Лечение:**
```
Parts := RefsStr.Split(Char.Chr(59));   // 59 — символ ";"
```
Системная сборка `System` подключена всегда и в списке не указывается.

### 13. Предупреждение «Переменная 'e' не используется»
**Симптом:** жёлтый значок в сообщениях компилятора (не ошибка).
**Причина:** в `Except On e: Exception Do` переменная `e` не упомянута в теле.
**Лечение:** добавить `e.Message` в текст журнала или ответа — заодно
будет понятнее причина сбоя.

### 14. Компиляция сборки, загруженной в текущий процесс, роняет процесс
**Симптом:** `Access violation at address ... in module KeSom.dll`,
процесс со формой завершается; в живых остаётся только тот, что компилировал.
**Причина:** попытка `ResolveAssembly` для сборки, экземпляр которой уже
загружен в этот же процесс, приводит к падению в нативном коде.
**Лечение — правило разделения:**
* прошивка живёт в **отдельной** сборке и свою сборку **не компилирует**;
* компилирует только чужие сборки — это безопасно (проверено: прошивка
  пережила три сбоя подряд);
* если нужно обновить модуль своей сборки — запись без компиляции
  (`NOCMP=1`), а компиляция после перезапуска формы.
**В коде это закреплено:** `KP_ASSEMBLY` = имя сборки прошивки, перед
компиляцией прошивка сверяет её с целевой и при совпадении не компилирует.

## Проверки перед запуском на стенде

Три проверки ловят типовые ошибки локально, без платформы:

| Проверка | Что находит | Запуск |
|---|---|---|
| Баланс и ключевые слова | незакрытые `Sub`/`If`/`Try`, зарезервированные имена | `node tools/agent-cli.js lint <файл>` |
| Линтер проекта | правила проекта, висячие `CreateForm` | `node tools/fore-lint-check.js Fore` |
| **Члены по словарю API** | `X.Член`, которого нет у типа `X` (например `IAssembly.Id`) | `node tools/check-members.js Fore` |

Третья проверка учится на рабочем коде проекта: обращения, уже встречающиеся
в модулях, считаются валидными — так отсекаются ложные срабатывания из-за
того, что справка не описывает наследование интерфейсов.
