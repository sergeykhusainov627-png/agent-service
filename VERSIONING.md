# Версионирование

## Что это

Репозиторий проекта `AgentService` — служебной сборки, через которую ведётся
разработка на платформе Форсайт: канал управления, прошивка, инструменты,
справочник найденных ограничений платформы.

## Зачем версии

До этого файлы жили только на диске, и уже дважды это мешало: текст в
репозитории Форсайта расходился с файлом на диске, и понять, какая версия
где, можно было только сверкой (`tools/compare-modules.js`). Теперь у каждой
правки есть коммит, и расхождение видно командой `git status`.

Второе: платформа не даёт откатить правку иначе как из бэкапа конкретного
модуля. Git даёт откат всего проекта — это независимая страховка.

## Что хранится

| Папка | Что | В репозитории |
|---|---|---|
| `Fore/Agent/` | канал и прошивка — рабочая часть | да |
| `Fore/*.fore` | зеркало исходников проекта планировщика для контекста | да |
| `tools/` | клиент канала, проверки, линтер | да |
| `docs/forsite/`, `docs/REFERENCE.md`, `docs/FORELANG.md` | справка платформы для сверки API | да |
| `docs/ПЛАТФОРМА-грабли.md` | найденные ограничения и проверенные приёмы | да |
| `inbox/`, `outbox/`, `k_inbox/`, `k_outbox/` | обмен с платформой | **нет** |
| `backup/`, `backup_main/`, `*.bak` | бэкапы модулей перед правкой | **нет** |
| `docs/forsite-online.zip` | онлайн-справка архивом, 1,2 МБ | **нет** |

Исключения — в `.gitignore`, там же объяснения.

## Правила коммитов

Сообщение в две части: короткая строка — что изменилось, затем пустая строка
и подробность. В подробности обязательно:

* **почему** изменение понадобилось;
* **какое ограничение платформы** затронуто (со ссылкой на
  `docs/ПЛАТФОРМА-грабли.md`);
* **чем проверено**: `agent-cli.js lint`, `fore-lint-check.js`,
  `check-members.js` или компиляция на стенде.

Пример:

```
Прошивка: убрана компиляция своей сборки

Компиляция сборки, загруженной в текущий процесс, роняет процесс
(Access violation в KeSom.dll, грабля №14). Прошивка теперь сверяет
целевую сборку с KP_ASSEMBLY и при совпадении не компилирует.

Проверено: agent-cli.js lint, check-members.js
```

## Ветки

* `master` — рабочее состояние, всё проверенное;
* отдельные ветки — под крупные изменения, если понадобится.

## Что не попадает в коммит

Перед коммитом проверяется, что в него не попали секреты и рабочие данные:

* нет паролей, токенов, ключей;
* нет выгрузок из репозитория Форсайт;
* нет бэкапов и файлов обмена.

Проверка: `git status --short` перед `git add`.

## Отправка на GitHub

Локальный репозиторий готов и закоммичен. Для отправки нужен доступ к
аккаунту — он у вас, я не могу и не должен его запрашивать в переписке.

Варианты:

1. **Вы добавляете remote и отправляете сами** — я подготовлю команды.
2. **Токен доступа с правом `repo`** — но передавать его в чат не стоит.
3. **SSH-ключ** — создаётся вами, приватная часть остаётся на машине;
   я тогда отправляю через `git@github.com`.

Уточнить аккаунт: ссылка `github.com/sergeykhusainov627` не открывается —
GitHub API отвечает «не найден». При этом в вашей настройке git
(`user.name = ser4ega`) указан существующий аккаунт
[github.com/ser4ega](https://github.com/ser4ega). Нужно подтвердить, куда
именно отправлять.
